# 间隔提醒：首版设计方案

日期：2026-10-24。状态：首版源码、调试 APK 与 Android 15 模拟器首轮检查已完成；尚未完成荣耀 90 真机和深度 Doze 验收。公开验证摘要见[首发验证记录](../test-results/s0-s1-preview/verification.md)，完整本机运行证据保留在本地测试结果目录。GitHub 结论见[项目对照与源码证据](research/github-references.md)。

## 1. 目标与范围

制作可直接安装在荣耀 90 的独立 Android APK。核心流程：设置间隔 → 开始 → 到时响一声 → 自动继续下一轮 → 用户停止。

首版功能：

- 单个循环提醒任务。
- 快捷选项：30 秒、50 秒、2 分钟。
- 自定义正整数与单位（秒/分钟），建议范围为 1 秒至 24 小时；空值、零、负数、非整数和超范围输入显示具体错误。
- 大字号显示下一次提醒的倒计时、当前间隔与已触发次数；音频请求失败单独提示。
- 开始、暂停/继续、停止，以及“试听提示音”。
- 内置约 0.5 秒的短提示音；提醒后自动结束声音并继续计时。
- 记住上次使用的间隔；再次打开可直接开始。
- 运行时显示常驻通知，提供暂停/继续和停止操作。
- 目标为退到桌面、切换应用、锁屏后仍继续提醒。

首版保持离线单机，不引入账号、云端、广告、多任务计划或统计报表。

## 2. 界面与交互

一个主页面，按从上到下排列：

| 区域 | 内容 |
| --- | --- |
| 标题 | 间隔提醒 |
| 间隔设置 | 数字输入框、秒/分钟切换 |
| 快捷设置 | 30 秒 / 50 秒 / 2 分钟 |
| 倒计时 | 大字号，例如 00:30 |
| 状态 | 未开始 / 运行中 / 已暂停；已触发 N 次；最近一次声音失败原因 |
| 主操作 | 开始；运行时变为暂停，暂停后变为继续 |
| 辅助操作 | 停止、试听提示音 |
| 运行条件提示 | 通知授权、电池优化状态、提示音使用闹钟音量 |

采用系统字体、足够大的触摸区域、避让状态栏和底部手势区；布局使用 dp 和自适应约束。倒计时不足一小时显示 MM:SS，一小时及以上显示 HH:MM:SS。实际字号缩放和荣耀 90 屏幕适配在交付阶段检查。

默认交互规则：

1. 按开始后，等待一个完整间隔再首次响铃。例如每 30 秒一次，响铃目标为开始后的第 30、60、90 秒。
2. 间隔按两次提醒开始时间计算，提示音时长不额外叠加到间隔中。
3. 暂停保留剩余时间，停止当前提示音并释放运行资源；继续时从剩余时间接着计时。
4. 停止立即取消后续提醒和正在播放的声音，回到未开始状态，保留设置值。
5. 运行和暂停期间锁定间隔编辑，停止后可修改。
6. 返回桌面继续运行；重新打开页面从服务读取真实状态，不创建第二个计时器。
7. 停止后再次开始，提醒次数从零计算。
8. 重启手机、系统强制停止或服务异常终止后，不自动恢复响铃；保留间隔，用户重新开始。不得从持久化标记误显示“正在运行”。

## 3. 技术实现

### 3.1 技术选型

采用 Kotlin 原生 Android + 简单 Views/XML 布局，直接调用 Android 计时、声音和通知接口。首版采用一个 Activity、一个前台 Service、一个小型计时状态对象及设置储存，避免引入跨平台运行时和数据库。开源项目用于对照设计；默认独立实现，不整体 fork，不引入候选项目的完整依赖体系。

建议最低 Android 10 / API 29，compileSdk/targetSdk 36。工具链拟固定 Gradle 9.3.1 / AGP 9.1.0，使用 AGP 内置 Kotlin 支持。已核实本机 JDK 17.0.2、Gradle 9.3.1 分发目录、SDK 36 和 Build Tools 36.0.0 均存在；版本组合与本项目依赖解析须在 S0 的实际构建中确认。只在当前进程设置 JAVA_HOME/ANDROID_HOME，不修改全局配置。

拟定核心文件职责：

| 文件 | 职责 |
| --- | --- |
| MainActivity.kt + 主页面布局 | 输入、倒计时显示、授权和系统设置入口 |
| ReminderService.kt | 唯一运行任务、调度、通知操作、生命周期和资源释放 |
| IntervalTimer.kt | 纯计时状态转换及下一次触发时间计算，便于定向验证 |
| ReminderSound.kt | 短音播放、音频焦点、停止与资源释放 |
| ReminderSettings.kt | 仅保存上次间隔，使用 SharedPreferences |

### 3.2 计时策略

- 使用 `SystemClock.elapsedRealtime()` 单调时钟记录截止时间，避免修改系统时间影响间隔。
- 前台服务持有唯一计时状态；页面只展示状态并发送操作。
- 根据绝对截止时间安排下一次回调；服务使用独立 HandlerThread 串行处理命令与调度，页面在主线程显示。UI 每秒刷新倒计时，关闭页面后停止 UI 刷新。
- Handler 使用 uptime 时钟，不能将 elapsedRealtime 的绝对值直接传给 postAtTime。每次计算 `max(0, deadlineElapsedMs - elapsedRealtime())` 后使用相对延迟，并在回调时再次读取 elapsedRealtime 校正；唤醒锁及省电豁免满足时才以锁屏精度目标验收。[5]
- 每次响铃后推进截止时间，避免用“播放完成后再延迟 N 秒”的方式累积误差。
- 系统异常延迟时只提醒一次，再推进至未来的下一个节拍；不连续补响多次。调试记录应保留延迟与跳过节拍，防止掩盖漏提醒。
- 开始与通知操作做幂等处理，连续点击不创建重复任务。

### 3.3 后台与锁屏

30 秒、50 秒和 2 分钟属于短周期连续任务。Android 普通重复闹钟为非精确调度；Doze 下允许空闲唤醒的闹钟也有频率限制，无法单靠这种方式满足短间隔目标。[1][2]

方案采用用户从可见页面启动的前台服务，并持续显示运行通知。Android 14 及以上拟声明 `specialUse` 类型和用途说明，说明用户发起、可随时停止的连续间隔计时需求；实施时校验目标 SDK 的声明和启动要求。[3]

前台服务本身不保证 CPU 在息屏后持续运行。为满足短间隔目标，活动会话期间按需持有部分唤醒锁，并引导用户将本应用设为不受电池优化限制；Doze 默认会忽略普通唤醒锁，获得电池优化豁免后才可在 Doze 内持有部分唤醒锁。[2][4]

具体要求：

- “开始”前检查通知权限与电池优化状态；未设置时说明影响，提供授权/设置入口。
- 没有电池豁免时仍可使用，但显示“锁屏提醒可能延迟”，不宣称稳定锁屏条件已满足。
- 通知拒绝时解释控制入口不可完整显示的影响，保持页面内可停止；禁止假装已授权。
- 唤醒锁仅在运行期间持有；暂停、停止、启动失败和服务销毁时释放，不保持屏幕常亮。
- 每次调度处理前台服务异常，避免出现页面倒计时运行、实际服务没有启动的假状态。
- 荣耀 90 的应用启动管理/后台活动限制需在真机核对；系统设置名称取决于实际 MagicOS 版本。
- 在用户明确强停应用后停止运行；不设计绕过系统强停的恢复机制。

持续短周期锁屏提醒会增加耗电；停止后释放资源是必要验收项。最终耗电和荣耀系统后台可靠性以真机结果为准。

### 3.4 提示音

- 内置自制约 0.4–0.5 秒的短音 WAV，采用 `SoundPool`、`maxStreams=1` 与 `USAGE_ALARM`，遵循系统闹钟音量；音频加载成功后再进入运行状态。音频资源由本项目生成并记录参数，不复制来源不明的铃声。
- “试听”与正式提醒共用同一音频路径，方便安装后立即检查音量。
- 提醒声不叠加；停止/暂停立即停止当前声音。运行中禁用试听，避免产生额外提醒声。
- 申请并正确释放瞬时音频焦点。通话、焦点被拒绝、音量为零等情况不强行调高音量或修改系统策略；记录未播放原因并让用户可见。
- 使用 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`，每次短音前请求、短音结束后释放，焦点丢失立即停止。拒绝时跳过本次声音，继续下一节拍，不在稍后补播过时提示音。Android 15+ 要求请求焦点时应用在前台或存在前台服务；服务应先进入前台状态再请求声音焦点。[6]
- `SoundPool.play()` 返回非零 streamId 只证明播放请求被接受，没有实际出声或播放完成回调。依据内置文件时长安排焦点释放，并保留立即 stop(streamId) 的能力；日志使用 PLAY_ACCEPTED/PLAY_REJECTED，不能伪造“扬声器已响”事件。[7]
- 不申请勿扰绕过权限。勿扰模式、蓝牙输出和实际外放效果作为验收场景，不承诺所有声音模式下都能外放。
- 不需要麦克风、文件读取或互联网权限；内置音频资源由应用直接读取。

所需系统能力以实际实现为准，预计包括通知权限（Android 13+）、前台服务权限、Android 14+ 的 specialUse 权限和 WAKE_LOCK。电池优化使用系统设置入口，不自动修改用户设置。首版调度方案不依赖精确闹钟授权。

定时精度的首轮验收目标：在满足运行条件的测试设备上，前台每次相对计划节拍的声音请求延迟不超过 1 秒，锁屏不超过 2 秒；属于待测目标，不是硬实时保证。按单调时间记录计划触发、实际调度、播放请求及停止；音频录制另测实际音头间距。出现漏触发、明显漂移或无故重复均为未通过。

局部测试范围：

- 间隔输入边界、首次触发、固定节拍、延迟后的处理、暂停/继续、停止、重复开始与状态重连。
- 30 秒、50 秒、120 秒使用实际时间，不能只加速计时代替用户场景验收。
- 切后台、锁屏、通知按钮、通知拒绝、电池豁免前后及强制 Doze。
- 静音/闹钟音量零、焦点拒绝的可见反馈与资源释放；通话和蓝牙效果优先留给真机核对。
- 调度日志和音频播放回调只能证明相应调用链；确认实际有声需模拟器音频录制/回环证据或人工听音记录，荣耀 90 扬声器需要真机验证。

默认只运行上述直接相关测试，不触发全量测试。临时脚本放 `tests/agent-temp/<任务标识>/`，结果、命令和日志放 `test-results/<任务标识>/`。

## 8. 状态、线程和资源契约

### 8.1 状态表

准备阶段仅显示“正在准备提示音”，准备失败不进入运行中。正式状态只设三个，服务持有唯一权威快照：

| 当前状态 | 操作/事件 | 下一状态与行为 |
| --- | --- | --- |
| 未开始 | 有效输入 + 开始成功 | 运行中；创建 sessionId，计数归零，deadline=now+interval |
| 运行中 | 到达截止时间 | 状态不变；触发一次短音，推进至未来节拍 |
| 运行中 | 暂停 | 已暂停；remaining=max(0, deadline-now)，取消回调和短音，释放焦点与唤醒锁 |
| 已暂停 | 继续 | 运行中；deadline=now+remaining，重新取得运行资源；remaining=0 时允许立即触发一次 |
| 运行中/已暂停 | 停止 | 未开始；sessionId 失效，清除回调，停止声音、服务与通知 |
| 任意 | 页面重建/回到前台 | 状态不变；从服务获取快照，禁止页面自建计时 |
| 任意 | 服务未存活/进程被回收/重启 | 未开始；只恢复间隔设置，要求用户重新开始 |

暂停时保留服务及“已暂停”通知用于继续/停止，不持有唤醒锁、不进行周期调度，也不播放声音；停止时结束服务。暂停状态仅保存在服务内存中，若系统回收服务则回到未开始，不承诺恢复暂停会话。

Service 使用 START_NOT_STICKY；不注册开机恢复，不使用额外闹钟或 WorkManager 复活任务。前台服务能降低被回收概率，不能保证任意手机上永不终止。用户从系统“活动应用”或设置强停时遵循系统行为。[9]

### 8.2 调度公式

内部统一 Long 毫秒。输入先转换和校验，秒范围 1–86400，分钟范围 1–1440，禁止先用 Int 相乘溢出。单位切换清空编辑值并展示示例，已保存的实际间隔不受影响；这样不会把 30 秒意外解释为 30 分钟。

每个到期回调读取 now：

```text
若 sessionId 或 generation 已失效、状态不是运行中：返回
若 now < deadline：按剩余时长重排，不响铃
否则：
  lateMs = now - deadline
  skippedPeriods = lateMs / intervalMs
  本次只请求播放一次
  nextDeadline = deadline + (skippedPeriods + 1) * intervalMs
```

例：30 秒节拍应为 30、60、90 秒，但回调到第 95 秒才执行：本次只请求一次，记录跳过两个节拍，下一次为第 120 秒；不能连续补响三次。出现这种跳拍时，该稳定性测试计为失败，不能用“成功恢复”覆盖漏触发。

所有会话命令与 due 回调在服务同一个队列执行。sessionId 标识一次开始到停止的会话，generation 标识当前有效调度批次。stop/pause 增加 generation 并取消音频尾部回调；异步加载、焦点和 UI 回调回到该队列后再次核对。继续保留 sessionId 并生成新的 generation；新开始生成新的 sessionId，防止旧任务和新任务串线。

### 8.3 通知与授权

- Android 13+ 按使用申请 POST_NOTIFICATIONS；拒绝后前台服务仍有系统约束下的运行入口，通知抽屉内的控制按钮可能不可见，页面必须显示这一事实。[8]
- 使用一个固定通知 ID、静音低重要性渠道、setOnlyAlertOnce；更新倒计时不能额外发声。渠道创建时不设置声音或振动。
- 通知显示间隔、状态和下一次提醒；采用系统 chronometer 倒计时，状态变化/每次提醒时更新，不每秒重复 notify。系统时间变化可能影响通知显示，服务调度仍以单调时钟为准；重新同步通知展示。
- 通知操作 PendingIntent 使用显式目标、不可变标记、独立 action 与当前会话标识，拒绝过时通知启动/继续新任务。
- 电池优化在页面实时检查，设置返回后刷新。未豁免仍可开始，显示锁屏可能延迟；真机设置入口不可用时给出普通应用信息入口，不硬编码未经验证的荣耀私有组件。
- 运行状态和暂停状态禁用试听。主页面未开始时试听不启动计时服务，音频失焦或离开页面即停止试听。
